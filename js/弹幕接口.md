# 弹幕接口来自哪里（橘子动漫 / 稀饭动漫 Next）

两个站点的弹幕是两回事：**稀饭动漫是自研后端 + 弹弹play 双路，橘子动漫网页端根本没有弹幕。**

---

## 一、稀饭动漫 Next（next.xifanacg.com）

前端是 Next.js，后端整个是 **Supabase**（Postgres + PostgREST + Edge Functions）。
站点把 Supabase 的 publishable key 直接写在浏览器 JS 里（公开的，不是秘密）：

```
项目地址  https://rzmsnqblptbceicadbyd.supabase.co
apikey    sb_publishable_aCb7uwyLN6H-sMjze4dRGA_2MDuROLF
（请求都要带：apikey: <key> 与 authorization: Bearer <key>）
```

### 1) 站内弹幕（自建，存 Supabase）

读（游标分页）：

```
POST {SB}/rest/v1/rpc/get_danmaku_page
body: {"p_episode_id": 121397, "p_after_id": 0, "p_limit": 500}
-> [{"id":586713,"v_time":4.835,"content":"签","color":"#FFFFFF","mode":"scroll"}, ...]
```

- `p_after_id` 传上一页最后一条的 `id`（游标，必须递增）；前端一次取 500 条、单集总量上限 8000 条
- 字段：`id`（游标）、`v_time`（出现时间，秒）、`content`、`color`、`mode`（`scroll`/…）

写（需要登录 + 通过站点的「社区礼仪/综合考试」考核）：

```
POST {SB}/rest/v1/rpc/send_danmaku
body: {"p_episode_id":N,"p_content":"文本","p_v_time":秒,"p_color":"#FFFFFF","p_mode":"scroll"}
-> {"ok":true,"danmaku":{...}} 或 {"ok":false,"error":"etiquette_required|comprehensive_required|banned|..."}
```

### 2) 外部弹幕（弹弹play，经自家域名代理）

站点先做一次「本站剧集 → 弹弹play 剧集」的映射，再取弹幕：

```
① 映射
POST {SB}/functions/v1/sync-dandan-mapping
body: {"anime_id": 3403, "episode_id": 121397}
-> {"ok":true,"source":"cached","dandan_anime_id":18727,"dandan_episode_id":187270001}

② 取弹幕（弹弹play 的标准评论接口，走他们的代理域名）
GET https://ext-danmaku.moedot.net/api/v2/comment/187270001?withRelated=true&chConvert=1
-> {"count":2293,"comments":[{"cid":1548867398076841984,"p":"0.00,1,25,16777215,...","m":"文本"}, ...]}
```

- `p` 是弹弹play 的 `时间,模式,字号,颜色,...` 格式，`m` 是文本
- `chConvert=1` = 简体转换，`withRelated=true` = 带上关联剧集
- 实测：第 01 集（站内 121397）`count=0`（没人发），第 03 集（站内 122479 → 弹弹 187270003）`count=2293`
- 前端还会把映射结果缓存进 `sessionStorage`，键名 `xfdm_dandan_map:<episodeId>`；取不到时播放器给的提示语是 `no_danmaku:"没有外部弹幕"`

### 3) 顺带：取流也是同一套

```
POST {SB}/functions/v1/issue-web-playback?forceFunctionRegion=ap-southeast-1
body: {"action":"auto","episode_id":121397}
-> {"ok":true,"resolved_action":"hls","url":"{SB}/functions/v1/issue-hls-playback?...&pt=<JWT>","expires_at":...}
```

返回的 `url` 直接是可播的 HLS 主播放列表（`#EXTM3U`），JWT 约 30 分钟有效，分片落在 `next.xfvod.pro/episodes/{anime}/{episode}/media-N/segment-M.ts?sign=...&t=...`。

### 本源怎么用弹幕

`js/xifanacg.js` 取流时会把 **弹弹play 那一路**按宿主的 `Result.danmaku` 格式挂上：

```json
{"parse":0,"url":"…","header":{…},"danmaku":[{"name":"弹弹play","url":"https://ext-danmaku.moedot.net/api/v2/comment/187270003?withRelated=true&chConvert=1"}]}
```

`count=0` 的集不挂（避免给播放器一个空文件）。站内弹幕是 POST RPC，没法当成「弹幕文件 URL」交给播放器，所以只在本文件里说明。

播放器侧要能看到弹幕：FongMi 的 **设置 → 弹幕** 里打开「加载弹幕」，并把弹幕来源选成「源优先」（`DanmakuSetting.isSpiderFirst()`）。
如果你的播放器不认弹弹play 的 JSON 弹幕格式，把站点配置的 `ext` 设成 `{"danmaku":"0"}` 即可关掉（不影响取流）。

## 二、橘子动漫（mgnacg.com）

**网页端没有任何弹幕。** 实测结论：

- 站点是 MacCMS + Streamlab 模板，播放器是自建的「橘子播放器」（muiplayer 外壳），托管在 `play.mknacg.top:8585`
- 这些文件里弹幕关键词命中数都是 0：`/static/js/playerconfig.js`、`/static/js/player.js`、`/static/Streamlab/js/ecscript.js`、`/static/Streamlab/js/assembly.js`、解析服务的 `cloudplay/js/*.js`、`muiplayer/js/*.js`
- 播放页 DOM 里也没有弹幕层、弹幕开关或任何 danmu 请求（`player_style=2`，纯 iframe 播放）

它首页挂的「APP DOWNLOAD」是个第三方播放器包：`https://ss1.lsst-cn.org/build/videoplayer111/latest/lsj_1200.apk`（直连 403，有防盗链）。
**如果你在某个地方看到过它的弹幕，那来自那个播放器/APP 自身，不是橘子的接口。**

### 顺带：橘子的取流链路（本源已实现）

```
1) /bangumi/{vod}-{sid}-{nid}/  ->  var player_aaaa = {from:"2_", url:"<密文>"}
2) /static/js/playerconfig.js   ->  player_list[from].parse（该线路的解析前缀，形如
                                    https://play.mknacg.top:8585/cloudplay/?url=）
   GET parse+url                ->  播放器页 var config = {url:"<密文>", vkey:"…"} + 两个 <meta id="now_x">
3) 密钥派生：把字母串按数字串升序重排得到 perm
     hex = MD5(perm + "Mknacg123321")   // vkey 是幌子，真正的盐在 setting.js 里写死
     iv  = hex[0:16]、key = hex[16:32]（作为 UTF-8 字符串，各 16 字节）
   AES-128-CBC/Pkcs7 解密 -> https://play.mknacg.top:9009/d/**/**.mknvideo?sign=**
```

⚠️ 那个直链会 302 到 `tjdownload.pan.wo.cn` 的 MP4，**播放时不能带 Referer**（带 Referer 返回 400，带 Origin 收到 CORS 403）。
